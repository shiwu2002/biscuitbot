# 工具数据优化设计：动态工具选择（Dynamic Tool Selection）

## 问题分析

### 现状
- `ToolRegistry.get_definitions()` 每次请求都返回**所有注册工具的完整 schema**（name + description + parameters JSON Schema）
- 15 个内置工具消耗 ~4,584 tokens；加上 MCP 工具可达 30-50+ 个（10,000+ tokens）
- 小模型（如 gemma-4-e4b）的上下文窗口被无关工具定义浪费
- 无任何工具过滤、检索或选择机制

### 数据测量（15 个内置工具）
| 工具 | desc | params | 总计 |
|------|------|--------|------|
| grep | 274 | 1,841 | 2,115 |
| exec | 567 | 1,523 | 2,090 |
| message | 735 | 1,127 | 1,862 |
| write_stdin | 383 | 1,434 | 1,817 |
| find_files | 252 | 1,018 | 1,270 |
| edit_file | 403 | 840 | 1,243 |
| ... | | | |
| **合计** | | | **18,339 chars (~4,584 tokens)** |

## 设计方案：三层工具选择

### 核心思路

```
用户消息
    ↓
ToolRetriever.select(message, registry)
    ↓
    ├── 始终包含工具（exec, read_file, web_search, message）
    ├── 关键词匹配工具（top-K by TF-IDF + token overlap）
    └── discover_tools 元工具（始终包含）
    ↓
模型收到：
    1. 选中工具的完整 schema（name + description + parameters）
    2. 所有工具的紧凑摘要（name + capability 一句话）— 在 system prompt 中
    3. discover_tools 元工具
    ↓
如果模型需要未选中的工具：
    → 调用 discover_tools("关键词" 或 "工具名")
    → 系统在 tool result 中返回匹配工具的完整 schema
    → 模型在下一轮调用该工具
```

### Layer 1: 工具能力索引（Tool Capability Index）

每个工具新增 `capability` 属性 — 紧凑的能力边界描述（1 句话），用于检索和摘要。

```python
# base.py — Tool 基类新增
@property
def capability(self) -> str:
    """One-sentence capability boundary for retrieval and compact summary."""
    return self._capability or self.description[:120]
```

示例：
| 工具 | capability |
|------|-----------|
| exec | "Execute shell commands with timeout and sandbox support" |
| read_file | "Read file contents with line range support" |
| grep | "Search file contents by regex pattern" |
| web_search | "Search the web and return results" |
| apply_patch | "Apply multi-file code edits with replace/add actions" |
| spawn | "Launch background subagent for long-running tasks" |

新增 `_always_include: bool = False` 标记始终包含的工具。

### Layer 2: 预检索（Pre-turn Retrieval）

`hczkbot/agent/tools/retriever.py`（新文件）：

```python
class ToolRetriever:
    """Lightweight tool retrieval using TF-IDF + token overlap."""

    def __init__(self, registry: ToolRegistry, *, max_tools: int = 10):
        self._registry = registry
        self._max_tools = max_tools
        self._index: dict[str, list[str]] = {}  # tool_name -> tokens
        self._idf: dict[str, float] = {}         # token -> idf score
        self._built = False

    def _build_index(self):
        """Build TF-IDF index from tool capabilities + descriptions + parameter names."""
        ...

    def select(self, query: str) -> list[str]:
        """Return top-K tool names relevant to *query*, plus always-include tools."""
        if not self._built:
            self._build_index()
        # 1. Always-include tools
        selected = {t.name for t in self._registry._tools.values() if t._always_include}
        # 2. TF-IDF scored retrieval
        query_tokens = self._tokenize(query)
        scores = self._score(query_tokens)
        for name, score in scores:
            if len(selected) >= self._max_tools:
                break
            selected.add(name)
        return list(selected)
```

**检索策略：**
- **分词**：小写化 + 按非字母数字分割 + 去停用词
- **索引内容**：工具 name + capability + description + parameter names + parameter descriptions
- **评分**：TF-IDF 加权 token overlap（无需 embedding 模型，纯 Python 实现）
- **始终包含**：标记 `_always_include = True` 的工具（exec, read_file, web_search, message, discover_tools）
- **top-K**：默认 10 个工具（可配置）

### Layer 3: 按需发现（On-demand Discovery）

新增 `discover_tools` 元工具：

```python
class DiscoverToolsTool(Tool):
    """Meta-tool: let the model request full schemas for tools not in the current selection."""
    name = "discover_tools"
    description = "Request full tool definitions by name or keyword. Use when you need a tool that isn't in your current tool set."
    parameters = {
        "type": "object",
        "properties": {
            "query": {"type": "string", "description": "Tool name or capability keyword"}
        },
        "required": ["query"]
    }
    _always_include = True

    async def execute(self, query: str) -> str:
        # Fuzzy match against all registered tools
        matches = self._registry.fuzzy_search(query)
        if not matches:
            return json.dumps({"error": "no matching tools found", "query": query})
        return json.dumps({
            "tools": [t.to_schema() for t in matches],
            "note": "These tools are now available. Call them in your next response."
        }, ensure_ascii=False)
```

模型调用 `discover_tools("screenshot")` → 系统返回 screenshot 工具的完整 schema → 模型在下一轮调用 `screenshot`。

### 紧凑工具摘要（Compact Tool Summary）

在 system prompt 中注入所有工具的紧凑摘要，让模型知道有哪些能力可用：

```markdown
## Available Tools (compact)

- exec: Execute shell commands with timeout and sandbox support
- read_file: Read file contents with line range support
- write_file: Write content to files
- edit_file: Edit files with old_text/new_text replacement
- grep: Search file contents by regex pattern
- find_files: Find files by name pattern
- web_search: Search the web and return results
- web_fetch: Fetch and extract content from URLs
- apply_patch: Apply multi-file code edits
- spawn: Launch background subagent for tasks
- message: Send messages to channels
- discover_tools: Request full tool definitions by name or keyword
- ...（所有工具，每个仅 1 行）

Tools already loaded with full schema: exec, read_file, web_search, message, grep
Use discover_tools to request other tools when needed.
```

### 配置

`ToolsConfig` 新增字段：

```python
tool_selection_mode: str = Field(
    default="all",  # "all" (current) | "dynamic" (new)
    validation_alias=AliasChoices("toolSelectionMode", "tool_selection_mode"),
)
dynamic_tool_max: int = Field(
    default=10,
    validation_alias=AliasChoices("dynamicToolMax", "dynamic_tool_max"),
    description="Max tools sent with full schema in dynamic mode",
)
```

- `all`：当前行为，所有工具完整 schema 发送（默认，向后兼容）
- `dynamic`：动态选择模式，仅发送选中工具的完整 schema + 所有工具的紧凑摘要

## 始终包含工具集

以下工具标记 `_always_include = True`（大多数 turn 都需要）：

| 工具 | 理由 |
|------|------|
| exec | 通用命令执行，几乎所有任务都需要 |
| read_file | 读取文件是基本操作 |
| web_search | 信息检索是常见需求 |
| message | 回复用户消息的核心工具 |
| discover_tools | 元工具，必须始终可用 |

其余工具（apply_patch, edit_file, write_file, grep, find_files, list_dir, web_fetch, spawn, run_cli_app, write_stdin, list_exec_sessions, screenshot, image_generation, cron 等）通过检索按需包含。

## Token 节省估算

| 模式 | 完整 schema tools | 紧凑摘要 | 预估 tokens |
|------|-------------------|----------|-------------|
| all（当前） | 15 | 0 | ~4,584 |
| dynamic | 5-10 | 15 × ~30 chars | ~2,500-3,500 |
| dynamic + 30 MCP | 5-10 | 45 × ~30 chars | ~3,000-4,000 |

MCP 工具越多，dynamic 模式的优势越大（从 10,000+ 降到 ~4,000）。
