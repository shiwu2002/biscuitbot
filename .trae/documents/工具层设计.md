# 工具层设计文档（Tool Layer Design）

> 本文档描述 `hczkbot` 工具层（`hczkbot/agent/tools/`）的整体架构、关键抽象、动态工具选择机制，以及新增/修改工具时需要遵守的契约。

---

## 1. 总览

工具层是 Agent 与外部世界交互的唯一通道：所有副作用（执行 shell、读写文件、调用 API、发送消息）都封装在 `Tool` 子类中。模型只能通过 OpenAI Function Calling 协议调用工具，不能直接执行任意代码。

### 1.1 设计目标

| 目标 | 实现策略 |
|------|----------|
| **统一抽象** | 所有工具继承 `Tool` ABC，实现 `name` / `description` / `parameters` / `execute` |
| **可发现** | `ToolLoader` 通过 `pkgutil.iter_modules` 自动扫描注册，无需手动登记 |
| **可检索** | 每个工具暴露 `capability` 一句话描述，`ToolRetriever` 用 TF-IDF 按需检索 |
| **可扩展** | 第三方插件通过 `entry_points(group="hczkbot.tools")` 注入 |
| **可配置** | 每个工具自带 `enabled(ctx)` + `create(ctx)` 工厂，按配置按需实例化 |
| **缓存友好** | `get_definitions()` 排序稳定（builtins 字母序 → MCP 字母序），prompt-prefix 缓存不被工具顺序抖动破坏 |
| **安全边界** | 工具内部实现 workspace 包含、SSRF 拦截、shell deny-list 等结构性防护 |

### 1.2 模块拓扑


## 2. 核心抽象

### 2.1 `Tool` ABC（`base.py`）

```python
class Tool(ABC):
    # --- 必须实现的抽象成员 ---
    @property
    @abstractmethod
    def name(self) -> str: ...
    @property
    @abstractmethod
    def description(self) -> str: ...
    @property
    @abstractmethod
    def parameters(self) -> dict[str, Any]: ...  # JSON Schema
    @abstractmethod
    async def execute(self, **kwargs: Any) -> Any: ...

    # --- 可选覆盖的属性 ---
    @property
    def read_only(self) -> bool: return False         # 是否无副作用（可并行）
    @property
    def concurrency_safe(self) -> bool: ...           # 是否可与其他 concurrency_safe 工具并行
    @property
    def exclusive(self) -> bool: return False         # 是否必须独占执行
    @property
    def capability(self) -> str:                       # 一句话能力边界（用于检索与摘要）
        return self._capability or self.description[:120]

    # --- 插件元数据 ---
    config_key: str = ""                               # 对应 ToolsConfig 的子配置键
    _plugin_discoverable: bool = True                  # 是否被 ToolLoader 自动扫描
    _scopes: set[str] = {"core"}                       # 注册范围（core / subagent / memory）

    # --- 动态工具选择元数据 ---
    _capability: str = ""                              # 显式能力描述（覆盖 description[:120]）
    _always_include: bool = False                      # dynamic 模式下始终发送完整 schema

    # --- 工厂方法 ---
    @classmethod
    def enabled(cls, ctx: ToolContext) -> bool: return True
    @classmethod
    def create(cls, ctx: ToolContext) -> Tool: return cls()
```

**契约要点：**

- `name` 必须是稳定的字符串标识符（不随实例变化），用作 `ToolRegistry` 的主键。
- `description` 是给模型看的长描述（可含示例、边界说明），**不参与** token-sensitive 的紧凑摘要。
- `capability` 是给检索器和紧凑摘要用的**一句话**能力边界（建议 ≤120 字符），优先返回 `_capability`，未设置时回退到 `description[:120]`。
- `parameters` 必须是合法的 JSON Schema dict（`{"type": "object", "properties": {...}, "required": [...]}`）。
- `execute` 是协程，返回 `str` 或 `list[dict]`（content blocks）。失败时返回以 `"Error"` 开头的字符串，`ToolRegistry.execute` 会自动追加 `[Analyze the error above...]` 提示。
- `enabled()` 在加载阶段调用一次，决定是否实例化。运行时切换需重启或重新加载。
- `create()` 是工厂方法，从 `ToolContext` 读取配置与依赖（bus、sessions、provider_loader 等）。

### 2.2 `tool_parameters` 装饰器

替代手写 `@property def parameters`，把 JSON Schema 绑定到类上并自动移除 `__abstractmethods__` 中的 `parameters`：

```python
@tool_parameters({
    "type": "object",
    "properties": {"path": {"type": "string"}},
    "required": ["path"],
})
class ReadFileTool(_FsTool):
    ...
```

每次访问返回 `deepcopy`，避免运行时误改 schema。

### 2.3 `Schema` ABC 与具体类型

`Schema` 是 JSON Schema 片段的抽象基类，提供 `validate_json_schema_value`（递归校验）和 `fragment`（实例/dict 归一化）。具体类型：

- `StringSchema` / `IntegerSchema` / `NumberSchema` / `BooleanSchema`
- `ArraySchema` / `ObjectSchema`
- `tool_parameters_schema(...)` — 链式构造辅助函数

`Tool.validate_params()` 调用 `Schema.validate_json_schema_value` 做参数校验，错误信息以 `;` 连接返回给模型。

## 3. 注册与执行：`ToolRegistry`

```python
class ToolRegistry:
    def register(self, tool: Tool) -> None: ...
    def unregister(self, name: str) -> None: ...
    def get(self, name: str) -> Tool | None: ...
    def has(self, name: str) -> bool: ...

    # --- 模型可见的 schema ---
    def get_definitions(self) -> list[dict]: ...
    def get_definitions_for_turn(self, query="", *, mode="all", max_tools=10) -> list[dict]: ...
    def get_compact_summary(self, selected_names: set[str] | None = None) -> str: ...

    # --- 按需发现 ---
    def fuzzy_search(self, query: str, *, limit: int = 5) -> list[Tool]: ...

    # --- 执行 ---
    async def execute(self, name: str, params: Any) -> Any: ...
    def prepare_call(self, name: str, params: Any) -> tuple[Tool | None, Any, str | None]: ...
```

### 3.1 `get_definitions()` 排序稳定性

返回 `[{"type": "function", "function": {...}}, ...]`，排序规则：

1. **builtins 优先**：name 不以 `mcp_` 开头的工具先返回
2. **MCP 滞后**：`mcp_*` 工具排在最后
3. **各自字母序**：builtins 和 MCP 分别按 name 字母排序

结果缓存到 `_cached_definitions`，下次 `register`/`unregister` 时失效。

**为什么这样排序？** OpenAI 等提供商的 prompt-prefix 缓存对 tools 数组顺序敏感。把"几乎总是存在"的 builtins 放前面，让缓存命中最大化。

### 3.2 `get_definitions_for_turn()` —— 动态选择的入口

```python
def get_definitions_for_turn(self, query="", *, mode="all", max_tools=10) -> list[dict]:
    if mode != "dynamic":
        return self.get_definitions()
    retriever = ToolRetriever(self, max_tools=max_tools)
    selected = set(retriever.select(query or ""))
    all_defs = self.get_definitions()
    return [d for d in all_defs if self._schema_name(d) in selected]
```

- `mode="all"`（默认）：行为与 `get_definitions()` 完全一致，**向后兼容**。
- `mode="dynamic"`：返回 `ToolRetriever.select()` 选中的子集，**保留 `get_definitions()` 的排序**，避免破坏缓存。

### 3.3 `prepare_call()` —— 调用前的归一化

```python
def prepare_call(self, name, params) -> tuple[Tool | None, Any, str | None]:
    # 1. 解析工具（含 "Did you mean" 建议）
    # 2. _coerce_params：JSON 字符串 → dict / 拆包 {"arguments": ...} 包装
    # 3. tool.cast_params：按 schema 做类型转换（"123" → 123）
    # 4. tool.validate_params：JSON Schema 校验
    # 返回 (tool, cast_params, error_msg_or_None)
```

**关键设计：** 失败信息会回传给模型（带 `[Analyze the error above...]` 后缀），让模型自我修正。

### 3.4 `execute()` —— 容错执行

```python
async def execute(self, name, params):
    tool, params, error = self.prepare_call(name, params)
    if error:
        return error + hint
    try:
        result = await tool.execute(**params)
        if isinstance(result, str) and result.startswith("Error"):
            return result + hint  # 工具自报错误也加提示
        return result
    except Exception as e:
        return f"Error executing {name}: {e}" + hint
```

异常被捕获并转为字符串，**永不向 agent loop 抛出** —— 保证单次工具失败不会中断整个 turn。

## 4. 加载与发现：`ToolLoader`

```python
_SKIP_MODULES = frozenset({
    "base", "schema", "registry", "context", "loader", "config",
    "file_state", "sandbox", "mcp", "__init__", "runtime_state",
})

class ToolLoader:
    def discover(self) -> list[type[Tool]]: ...
    def load(self, ctx, registry, *, scope="core") -> list[str]: ...
```

### 4.1 发现流程

1. `pkgutil.iter_modules(hczkbot.agent.tools.__path__)` 枚举模块
2. 跳过 `_SKIP_MODULES`（基础设施模块）和以 `_` 开头的私有模块
3. `importlib.import_module` 导入模块
4. 扫描模块内所有 `Tool` 子类，过滤条件：
   - 非抽象（`__abstractmethods__` 为空）
   - `_plugin_discoverable is True`
   - 类名不以 `_` 开头
5. **按类名字母序排序**，确保注册顺序稳定

### 4.2 注册流程

```python
for tool_cls in self.discover():
    if scope not in tool_cls._scopes: continue
    if not tool_cls.enabled(ctx): continue
    tool = tool_cls.create(ctx)
    if registry.has(tool.name):
        # 内置优先：插件与内置同名时跳过插件
        ...
    registry.register(tool)
```

### 4.3 第三方插件

通过 `entry_points(group="hczkbot.tools")` 注册：

```toml
# pyproject.toml
[project.entry-points."hczkbot.tools"]
my_tool = "my_package.tools:MyTool"
```

加载时与内置工具合并，**内置同名时内置优先**。

### 4.4 手动注册

某些工具需要运行时状态引用，无法走自动发现：

| 工具 | 原因 | 注册点 |
|------|------|--------|
| `MyTool` | 需要 `AgentLoop` 实例引用 | `loop._register_default_tools()` |
| `ScreenshotTool` | 需要 `vision_provider_loader` | `loop._register_default_tools()` |
| `DiscoverToolsTool` | 需要 `bind_registry(self.tools)` | `loop._register_default_tools()`（dynamic 模式才注册） |

## 5. 动态工具选择（Dynamic Tool Selection）

### 5.1 动机

| 现状 | 问题 |
|------|------|
| 15 个内置工具消耗 ~4,584 tokens | 小模型上下文被工具定义浪费 |
| 加上 MCP 可达 30-50+ 工具 | 10,000+ tokens 用于工具定义 |
| `get_definitions()` 每次返回全部 | 无任何过滤/检索机制 |

### 5.2 三层设计

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: 能力索引（capability 属性）                          │
│  - 每个工具一句话能力边界                                      │
│  - 用于检索评分 + 紧凑摘要                                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Layer 2: 预检索（ToolRetriever, TF-IDF）                     │
│  - 每轮 turn 开始时按用户消息选 top-K 工具                     │
│  - always_include 工具无条件包含                              │
│  - 选中工具发送完整 schema                                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Layer 3: 按需发现（DiscoverToolsTool 元工具）                │
│  - 模型调用 discover_tools("screenshot") → 返回完整 schema    │
│  - 下一轮即可调用该工具                                       │
│  - 始终包含在选中集合中                                       │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 Layer 1：`capability` 属性

```python
class Tool(ABC):
    _capability: str = ""  # 显式设置时优先
    _always_include: bool = False

    @property
    def capability(self) -> str:
        return self._capability or self.description[:120]
```

**始终包含工具集（`_always_include = True`）：**

| 工具 | 理由 |
|------|------|
| `exec` | 通用命令执行，几乎所有任务都需要 |
| `read_file` | 读取文件是基本操作 |
| `web_search` | 信息检索是常见需求 |
| `message` | 回复用户消息的核心工具 |
| `discover_tools` | 元工具，必须始终可用 |

其余工具（`apply_patch` / `edit_file` / `write_file` / `grep` / `find_files` / `list_dir` / `web_fetch` / `spawn` / `run_cli_app` / `write_stdin` / `list_exec_sessions` / `screenshot` / `generate_image` / `cron` / `long_task` / `complete_goal` / `my`）通过检索按需包含。

### 5.4 Layer 2：`ToolRetriever`（`retriever.py`）

```python
class ToolRetriever:
    def __init__(self, registry, *, max_tools=10): ...
    def select(self, query: str) -> list[str]: ...
```

**检索策略：**

1. **分词**：小写化 + 按非字母数字分割 + 去停用词 + 长度 ≥2
2. **索引内容**：`name` + `capability` + `description` + 参数名 + 参数描述
3. **评分**：TF-IDF 加权 token overlap
   - TF 归一化：`(1 + log(tf)) * idf / sqrt(doc_len)`
   - **名称命中加权 ×2**：query token 出现在工具名中时额外加权
4. **始终包含**：`_always_include = True` 的工具无条件加入（排在前面）
5. **top-K 截断**：默认 10 个，受 `dynamic_tool_max` 配置控制

**为什么不用 embedding？**

- 工具语料小（10-50 个），关键词匹配足够
- 避免网络/embedding 依赖，延迟可预测
- 可解释性强，调试方便
- `discover_tools` 元工具兜底长尾

### 5.5 Layer 3：`DiscoverToolsTool`（`discover.py`）

```python
class DiscoverToolsTool(Tool):
    name = "discover_tools"
    _always_include = True

    @classmethod
    def enabled(cls, ctx) -> bool:
        return ctx.config.tool_selection_mode == "dynamic"

    def bind_registry(self, registry): ...

    async def execute(self, query: str, limit: int | None = None) -> str:
        matches = self._registry.fuzzy_search(query, limit=effective_limit)
        return json.dumps({"tools": [t.to_schema() for t in matches], "note": ...})
```

**调用流程：**

```
模型：discover_tools("screenshot")
  ↓
系统：fuzzy_search → 返回 screenshot 完整 schema
  ↓
模型：下一轮调用 screenshot(question="...")
```

**`fuzzy_search` 评分：**

- 精确名称匹配：+100
- 名称子串匹配：+20
- token overlap：+4/词
- 全部 query token 命中：+5 bonus

### 5.6 紧凑工具摘要

dynamic 模式下，system prompt 注入所有工具的一行摘要：

```markdown
# Available Tools (compact summary)

- apply_patch: Apply multi-file code edits with replace/add actions in a single call.
- complete_goal: Mark the active sustained goal as finished after verifying required work.
- cron: Schedule reminders and recurring cron-driven tasks (add/list/remove).
- discover_tools: Request full tool definitions by name or keyword when a needed tool is not in your current tool set.
- edit_file: Edit a file by exact old_text/new_text replacement with fuzzy fallback.
- exec: Execute shell commands (build, test, git, package managers) with timeout, sandbox, and deny-list guards. (loaded)
- find_files: Find files by path fragment, glob, or file type; returns workspace-relative paths.
- grep: Search file contents by regex pattern; returns matching paths or lines with context.
- list_dir: List directory entries (optionally recursive, skips common junk dirs).
- long_task: Begin or replace a long-running sustained objective tracked on the session.
- message: Proactively send messages or file attachments to users/channels (reminders, cross-channel delivery). (loaded)
- read_file: Read text, image, or document files (PDF/DOCX/XLSX/PPTX) with line-range pagination for analysis before edits. (loaded)
- screenshot: Capture a screenshot and analyze it with the configured vision model.
- spawn: Launch a background subagent for long-running or parallel tasks.
- web_fetch: Fetch a URL and extract readable content as markdown/text for analysis.
- web_search: Search the web for current information; returns titles, URLs, and snippets. (loaded)
- write_file: Write or overwrite file contents (text files only).

Tools already loaded with full schema are marked (loaded).
Call `discover_tools` to request the full schema for any other tool listed above before invoking it.
```

**Token 节省估算：**

| 模式 | 完整 schema 工具 | 紧凑摘要 | 预估 tokens |
|------|-------------------|----------|-------------|
| all（默认） | 15 | 0 | ~4,584 |
| dynamic | 5-10 | 15 × ~50 chars | ~2,500-3,500 |
| dynamic + 30 MCP | 5-10 | 45 × ~50 chars | ~3,000-4,000 |

MCP 工具越多，dynamic 模式优势越大。

## 6. 集成点

### 6.1 `AgentLoop._register_default_tools()`（`loop.py`）

```python
def _register_default_tools(self):
    ctx = ToolContext(config=self.tools_config, ...)
    loader = ToolLoader()
    registered = loader.load(ctx, self.tools)

    # 手动注册需要运行时状态的工具
    if self.tools_config.my.enable:
        self.tools.register(MyTool(runtime_state=self, ...))
    if self.tools_config.screenshot.enable:
        self.tools.register(ScreenshotTool(vision_provider_loader=...))

    # DiscoverToolsTool 在 dynamic 模式下被 loader 自动注册
    # 这里绑定 registry 引用，让元工具能搜索所有工具
    discover_tool = self.tools.get("discover_tools")
    if discover_tool is not None:
        discover_tool.bind_registry(self.tools)
```

### 6.2 `AgentRunSpec`（`runner.py`）

新增字段透传配置：

```python
@dataclass(slots=True)
class AgentRunSpec:

    dynamic_tool_max: int = 10
```

### 6.3 `AgentRunner._request_model()`（`runner.py`）

每轮 LLM 调用前计算工具子集：

```python
def _request_model(self, spec, messages, hook, context):
    kwargs = self._build_request_kwargs(
        spec,
        messages,
        tools=spec.tools.get_definitions_for_turn(
            _latest_user_query(messages),  # 从 messages 提取最新 user 消息
            mode=spec.tool_selection_mode,
            max_tools=spec.dynamic_tool_max,
        ),
    )
```

`_latest_user_query` 反向遍历 `messages`，返回最近一条 user 消息的文本（支持多模态 list content）。

### 6.5 `AgentLoop._build_initial_messages()` 与 `_run_main_loop()`

dynamic 模式下，在构造 messages 时注入紧凑摘要：

```python
tool_compact_summary = None
if self.tools_config.tool_selection_mode == "dynamic":
    retriever = ToolRetriever(self.tools, max_tools=self.tools_config.dynamic_tool_max)
    selected = set(retriever.select(msg.content or ""))
    tool_compact_summary = self.tools.get_compact_summary(selected)

messages = self.context.build_messages(..., tool_compact_summary=tool_compact_summary)
```

## 7. 工具开发指南

### 7.1 新增工具的步骤

1. **创建模块**：`hczkbot/agent/tools/my_tool.py`
2. **定义 Tool 子类**：

   ```python
   from hczkbot.agent.tools.base import Tool, tool_parameters

   @tool_parameters({
       "type": "object",
       "properties": {"input": {"type": "string"}},
       "required": ["input"],
   })
   class MyTool(Tool):
       _scopes = {"core"}
       _capability = "One-sentence description of what this tool does."

       @property
       def name(self) -> str:
           return "my_tool"

       @property
       def description(self) -> str:
           return "Long description for the model..."

       async def execute(self, input: str) -> str:
           return f"processed: {input}"
   ```

3. **可选配置**：在 `ToolsConfig` 添加子配置，覆盖 `enabled()` / `create()` / `config_cls()`
4. **测试**：在 `tests/agent/tools/test_my_tool.py` 写测试

### 7.2 何时设置 `_capability`

- **建议显式设置**：当 `description[:120]` 不能准确概括能力边界时
- **必须设置**：当工具名与能力无关（如 `my` 是配置检查工具）
- **可省略**：当 `description` 前半句已经是清晰的一句话时

### 7.3 何时设置 `_always_include = True`

仅在以下情况设置：

- 工具在大多数 turn 都会被用到（如 `exec` / `read_file`）
- 工具是元工具，必须始终可用（如 `discover_tools`）
- 工具是消息通道（如 `message`）

**反例：** `screenshot` / `generate_image` / `cron` 等低频工具不应设置，避免占用 dynamic 模式的 token 预算。

### 7.4 何时设置 `_plugin_discoverable = False`

- 工具需要运行时状态引用，无法通过 `create(ctx)` 工厂构造（如 `MyTool` 需要 `AgentLoop` 实例）
- 工具需要特殊的依赖注入（如 `ScreenshotTool` 需要 `vision_provider_loader`）

此时需在 `loop._register_default_tools()` 手动注册。

### 7.5 工具命名约定

- **小写下划线**：`read_file` / `web_search` / `discover_tools`
- **MCP 工具自动加 `mcp_` 前缀**：`mcp_<server>_<tool>`
- **避免与内置工具同名**：插件同名会被内置覆盖

### 7.6 错误处理约定

- `execute` 失败时返回 `"Error: <reason>"` 字符串，**不要抛异常**
- `ToolRegistry.execute` 会自动捕获异常并加上 `[Analyze the error above...]` 提示
- 结构性错误（参数缺失等）由 `prepare_call` 在调用前拦截

## 9. 安全边界

工具层是 Agent 与外部世界交互的唯一通道，所有副作用都封装在工具内。以下安全机制**始终开启**，不受 `guard_level` 影响：

| 机制 | 实现位置 | 说明 |
|------|----------|------|
| **workspace 包含** | `path_utils.resolve_workspace_path` | 文件操作限制在 workspace 内 |
| **SSRF 拦截** | `web.py` / `shell.py` | 拦截内网 IP 与 localhost 服务访问 |
| **路径遍历** | `path_utils` | 拦截 `..` 与符号链接逃逸 |

以下机制受 `guard_level` 控制（详见 `security/guard_level.py`）：

| 机制 | standard | minimal | off |
|------|----------|---------|-----|
| Shell catastrophic deny-list（`rm -rf` / `mkfs` / `dd` / fork bomb） | ✓ | ✓ | ✗ |
| Shell friction deny-list（`curl \| sh` / 状态文件保护） | ✓ | ✗ | ✗ |
| Untrusted content banner（web_fetch 结果） | ✓ | ✗ | ✗ |
| Untrusted content snippet（identity 模板） | ✓ | ✓ | ✗ |
