# 产品摄影（商业品牌视觉）

> **与常见做法相反：最终提示词由你自己写，不存在帮你兜底的私有增强后端。**
> 本技能给你的是「拍摄语言 + 追问脚本 + 变体纪律」，**提示词得你亲手扩写**
> （`docs/generate_image.md` 明确要求「调用前必须先优化提示词」）。
> 通用手法（镜头语言、图生图怎么写、文字渲染、画幅、安全边界）见
> `media-generation-craft` 技能目录下的 `references/prompt-engineering.md`。

以「产品图」为起点做品牌级营销图。**有产品就算产品摄影**；纯文生图不带产品去
`media-generation-craft`；要上架的合规交付物去 `marketplace-cards`。

## 生成能力从哪来（先看这一节）

**本技能只提供「怎么做得对」的方法，不提供生成引擎。** 真正的生成能力必须现场发现，
不同用户、不同时间的可用情况可能完全不同。按下面顺序判断，**不要假设任何模型名**。

1. **先发现，再动手。** 用 `discover_tools("生成图片")` / `discover_tools("生成视频")`
   确认当前到底有哪些生成工具可用。本项目的原生工具是 `generate_image`（图片）与
   `generate_video`（视频），调用前用 `read_file` 读它们的使用说明
   （`docs/generate_image.md` / `docs/generate_video.md`），按真实参数传参。
2. **优先用原生工具。** 用户在本机配置里已经决定启用哪些厂商与模型，那是他的选择，
   不要替他改、也不要在提示词里写死某个模型名。需要的是「具备某种能力的模型」——
   例如「文字渲染准确的模型」「角色一致性强的模型」「支持参考图的编辑模型」——
   然后从实际可用的工具与模型里挑最合适的一个，并在回复里说明你挑了哪个、为什么。
   工具的 `model` / `provider` 参数留空即走用户配置的默认值，**除非用户明确指定**。
3. **用户配了 MCP 生成服务就优先用它。** 如果 `discover_tools` 或
   `cold_storage` 找到 `mcp_` 前缀的生成类工具（用户在 `tools.mcpServers` 里
   自己接的服务），说明用户有意为此付费/自建，应当优先使用；同样先读它的说明再调用。
4. **一个都没有时，诚实说明，不要硬编。** 如果确实找不到任何可用的生成工具：
   - 明确告诉用户「当前没有可用的图像/视频生成能力」，并指出这是开关问题不是能力问题
     （图片生成开关：`tools.imageGeneration.enabled`；视频生成开关：
     `tools.seedanceVideo.enabled`，可在「模型厂商」页配置密钥）。
   - **绝对不要**改用 `exec` 去调某个第三方 CLI、去装某个未配置的服务、或凭空编造一个
     看起来像结果的图片路径。也不要假装生成成功。
   - 可以退而求其次：如果你能用 `exec` + 本地库（如 ffmpeg、Pillow）做出**确定能做出**的
     替代产物（例如纯色占位图、文字海报），先说明这是替代方案，再做。
   - 把选择权交回用户，问他是要打开开关、配置厂商，还是换一个不需要生成的做法。

> 本技能的 10 种模式**不绑定模型**——模式决定的是**提示词结构与拍摄语言**，
> 具体由哪家模型渲染、用哪个工具，由上面第 2 条现场决定。

## 模式路由表

先按**意图**选模式，不要只看关键词。两个模式都可能适用时，**选更具体的那个**。

| 模式 | 用户想要的是… |
|---|---|
| `product_shot` | 产品在纯色/影棚/目录级背景上的标准成品图 |
| `lifestyle_scene` | 产品在真实环境里被使用，有手、有动作、有氛围 |
| `closeup_product_with_person` | 手/局部人脸 + 产品的紧特写——涂抹、握持、演示 |
| `moodboard_pin` | 2:3 竖版、Pinterest 风格的情绪板/种草图 |
| `hero_banner` | 网站/邮件/活动页用的宽幅头图 |
| `social_carousel` | 3–10 张有连贯关系的社媒轮播图 |
| `ad_creative_pack` | 成套的静态广告变体（Meta / TikTok / 信息流） |
| `virtual_model_tryout` | 产品被虚拟模特穿戴/使用（服装、配饰、上身效果） |
| `conceptual_product` | 超现实 / CGI 感 / 悬浮 / 飞溅 / 雕塑感产品图 |
| `restyle` | 改**已有图**的审美、情绪或季节氛围，不改主体 |

**判定规则**（按此逐条匹配）：

- 产品 + 干净的 / 白色 / 影棚 / 目录 → `product_shot`
- 产品 + 场景 / 在使用 / 厨房 / 户外 / 咖啡馆 / 健身房 → `lifestyle_scene`
- 手握着 / 脸和产品同框 / 涂抹演示 → `closeup_product_with_person`
- Pinterest、竖版种草、情绪板 → `moodboard_pin`
- hero、banner、网站头图、落地页、邮件头图、宽幅 → `hero_banner`
- 轮播、多张滑动、多图一套 → `social_carousel`
- 广告、广告组、付费投放、信息流 → `ad_creative_pack`
- 模特穿、试穿、上身、穿搭、lookbook → `virtual_model_tryout`
- 悬浮、漂浮、飞溅、冻结瞬间、超现实、CGI、雕塑感 → `conceptual_product`
- 改**已有图**的审美/情绪/季节，但主体不变 → `restyle`

**冲突时的取舍**：

- 「把产品放在厨房台面上的 Pinterest 竖版图」→ `moodboard_pin`（平台形态优先）
- 「展示产品使用场景的横幅头图」→ `hero_banner`（横幅形态优先）
- 「产品在不同场景里的轮播图」→ `social_carousel`（多图形态优先）
- 「有人涂抹我的精华的紧特写」→ `closeup_product_with_person`（更具体的品类优先）

**每个模式的提示词骨架、专属易错点、默认画幅**见
`references/mode-playbook.md`（本技能目录下）——**选定模式后先 `read_file` 读它**，
里面有该模式「先写什么、后写什么」的顺序。

## 生成前的追问

**最多问 4 个问题**，且必须给**有标签的选项**，不要开放式提问。上下文里已经明确的
（用户上传了图、上一轮说过、品牌资料里有）**直接跳过，别问**。

### A 类 —— 上传了产品图，说「帮我做几张图 / 拍几张」

1. 要几张？`[1 张 / 3 张 / 5 张]`
2. 什么风格？`[干净影棚 / 生活场景 / 概念超现实 / 有模特 / 其他]`
3. 用在哪？`[电商详情 / 社媒 / Pinterest / 付费广告 / 网站头图]`
4. 有品牌色要匹配吗？（上下文已明确就跳过）

### B 类 —— 上传了产品图，并且指名了用途

例如「给我的产品做广告图」「做一张 Pinterest 竖版」「做一张横幅头图」。模式已经很清楚，
**只问缺口**：

1. 要几张？（多输出模式才问）
2. 这次的卖点 / 情绪 / 钩子是什么？
3. 有特别想强调的地方吗？

### C 类 —— 只有文字，没有产品图

1. 能上传一张产品图吗？（**强烈建议**——有参考图的效果高很多）
2. 上传不了的话，描述一下产品：品类、包装、颜色、最显眼的特征。
3. 什么风格？（同 A 类选项）
4. 用在哪？

### D–F 类

改已有图（`restyle`）、模特上身（`virtual_model_tryout`）、需求很含糊这三种情况的追问脚本，
见 `references/mode-playbook.md` 末尾的「追问脚本（D/E/F）」。

## 生成

把追问得到的答案**扩写成该模式的完整提示词**，调 `generate_image`：

```
generate_image(
  prompt="<按 mode-playbook 的骨架扩写好的详细提示词>",
  reference_images=["<用户的产品图本地路径>"],   # 有产品图就一定要传
  aspect_ratio="<按模式默认画幅，或用户指定>",
  count=<张数>
)
```

- **有产品图就必须传 `reference_images`**——这是产品摄影的根，没有它生成的产品会和实物不一样。
- **画幅**：按模式的惯例给默认值（见 mode-playbook），用户明确要求其他画幅时以用户为准。
- **分辨率**：电商成品图建议 2K 起步，需要放大或印刷时更高。

## 多图变体纪律

这是最容易做砸的一环：

- `count` 调大时，**让每张在预设、光线、角度、配色上真正不同**——不要用同一句提示词
  换几个形容词充数。要真的换机位、换光线方案、换背景，而不是换个说法。
- **生成后自己先看一眼**。发现同质化就重写提示词重来，别直接交付。
- `social_carousel` 与 `ad_creative_pack`：**变体数 = 页数**，且整套必须**锁死同一套视觉系统**
  （配色、字体、版式、光线语言一致）——先定第 1 张为基准，后续图传它做 `reference_images`。
- 「换个季节 / 换个节日」的系列图同理：先定基准图，再做变体。

## 交付

- 结果持久化为本地产物，工具返回本地路径。
- **用 `message` 工具的 `media` 参数把图发给用户**。
- 回复保持简短：交付了什么、几张、分别是什么模式/用途。
- **不要把模式名、提示词全文、本地路径贴给用户**，也不要点评内部实现。
- 有失败的图就简短说明哪张失败、为什么，不要假装全部成功。

## 常见错误

| 错误 | 后果 |
|---|---|
| 一条消息里问了超过 4 个问题 | 用户嫌烦，直接放弃 |
| 模式选错（如用户要 Pinterest 图却给了 `product_shot`） | 画幅和调性都不对，得重做 |
| 有产品图却没传 `reference_images` | 生成的产品和实物对不上，等于废图 |
| 变体只是换个说法 | 一堆几乎一样的图，浪费生成额度 |
| 把拼好的提示词回贴给用户 | 用户要的是图，不是提示词 |
| 提示词里写死某个模型名 | 用户没配该模型时直接失败 |
| 找不到生成工具就编一个结果路径 | **最严重**——欺骗用户。必须如实说明 |
