# 提示词工程（图像 / 视频）

`media-generation-craft` 的按需加载参考。写提示词前读这一份，正文只讲流程，细节在这里。

## 基础知识：四个维度

生成模型普遍对**具体、可感**的描述响应更好，对抽象、笼统的词响应差。一条好提示词通常
覆盖四个维度：

- **主体 + 场景 + 风格** —— 「一只红狐蜷在落雪的松林里，黄昏金色光线，电影感」
- **镜头** —— 焦段（35mm / 85mm）、机位（低角度、俯拍）、运动（推近、跟拍）
- **光线** —— 轮廓光、霓虹辉光、阴郁逆光、柔光箱主光
- **风格 / 媒介** —— 油画、水彩、摄影、动画、3D 渲染、胶片

**长度控制**：一般控制在约 200 token 以内。提示词过长会稀释重点，模型反而顾此失彼——
关键字句前置，次要细节后置。

## 图生图（编辑已有图片）

传了参考图（`reference_images`）时，提示词要描述**要改什么**，不要重新描述原图。

```
# 差：把原图内容又描述了一遍 → 模型可能重画，原图特征丢失
"一个棕发男人穿皮衣拿着咖啡，改成动画风格"

# 好：只说改动
"转换为动画风格，色彩鲜艳，柔和的赛璐璐上色"
```

常见编辑意图的写法：

| 意图 | 提示词怎么写 |
|---|---|
| 换风格 | 只写目标风格与色感，不写原图内容 |
| 换背景 | 写新背景的材质/光线/深度，并说明「保持主体不变」 |
| 去物 | 写「移除 X，补全它后面的背景」，并说明背景应该是什么 |
| 换材质/颜色 | 写目标材质与颜色，点名是哪个部位 |

**保留项要显式写出来**：「保持人物面部特征不变」「保持产品外观与包装文字一致」——
不写的话模型不保证保留。

## 图生视频（让图片动起来）

`generate_video` 的 `image_urls` **第一个元素会被当作首帧参考**。提示词写运动：

- **运镜动词**：推近、拉远、横移、环绕、跟随、手持晃动、慢速推进、快速甩镜
- **主体动作**：「舞者旋转」「烟雾缓缓上升」「猫转头看向镜头」
- **不要重复描述静态画面**——首帧已经给了模型，把提示词预算全留给运动。

多片段连贯：把上一段的**尾帧**放在下一段 `image_urls` 的**首个位置**，即可接着上一段继续动。

## 否定式表述

`generate_image` 与 `generate_video` **都没有 `negative_prompt` 参数**，所以别写「不要 X」，
改用正面表述——正面描述比否定描述对模型更有效：

| 不要写 | 改成 |
|---|---|
| 「没有模糊」 | 「锐利清晰，细节分明」 |
| 「没有人」 | 「空旷无人的荒野」 |
| 「不要卡通感」 | 「写实摄影质感，真实材质与光影」 |
| 「不要文字」 | 「画面纯净，无任何文字与标识」 |

## 画幅

| 取值 | 适用 |
|---|---|
| `16:9` | 横屏、宽幅、电影感、网站横幅 |
| `9:16` | 竖屏、短视频、手机端 |
| `1:1` | 方形、头像、电商主图 |
| `4:3` / `3:4` | 常规横/竖构图 |
| `21:9` | 超宽银幕感 |

**注意支持的取值取决于所配厂商，别想当然**：

- **`generate_image`**：`docs/generate_image.md` 只举例了 `1:1 / 16:9 / 9:16 / 4:3`。
  其余取值能否用**取决于实际启用的厂商**——不确定时优先用这四个，或干脆不传让工具走默认。
- **`generate_video`**：文档列出 `16:9 / 9:16 / 1:1 / 4:3 / 3:4 / 21:9 / adaptive`，
  但**部分厂商只支持其中一部分**，越界的值会被**静默丢弃并回落默认值**——不会报错，
  只会给你一个比例不对的成品。传之前先读 `docs/generate_video.md` 的厂商参数差异表。

## 文字渲染（Logo / 海报 / 封面）

不同模型的文字渲染准确度差异极大，这是**必须生成后人工核对**的一项：

1. 把要出现的文字**逐字**写进提示词，并用引号标出，例如：
   「招牌上写着 "夏奈儿" 三个字，中文黑体，居中排布」
2. 说明字体气质（黑体/宋体/手写/衬线）、粗细、位置与颜色。
3. **生成后逐字核对有没有错字、缺笔、多余字**。有错字时**换一个擅长文字渲染的模型重试**，
   不要反复微调同一句提示词——文字渲染是模型能力问题，不是措辞问题。

## 视频专属

提示词按 **主体 → 动作 → 环境 → 运镜 → 风格** 组织，越具体越好：

- **主体**：谁 / 什么（外貌、材质、数量）
- **动作**：在做什么、如何运动（快慢、幅度、轨迹）
- **环境**：时代、地点、时间、光线、天气、氛围
- **运镜**：特写/全景、推拉摇移、跟随、手持、无人机
- **风格**：写实 / 电影感 / 动漫 / 3D / 纪录片，可加画质词（「浅景深」「赛博朋克色调」）

```
# 弱
"一只猫在弹钢琴"

# 强
"一只毛茸茸的橘猫坐在三角钢琴前，前爪按下琴键，特写镜头，暖黄色台灯打光，
 浅景深，电影感，节奏舒缓"
```

其他要点：

- `generate_audio` 默认开启（音画同步生成音频）。要环境音/口型同步就保持开启；
  只要静默画面再单独配音，传 `false`。
- `duration` 与 `resolution` 的可用范围随厂商与模型版本变化，且**带参考素材（图/视频/音频）
  时不要传 `resolution`**——该模式由参考素材推导分辨率，显式传入会被拒绝。
- 需要配音旁白时用 `text_to_speech`，配音驱动口型的完整流程见 `short-drama-production` 技能
  （其中也记录了参考音频的时长上限）。

## 安全边界

多数厂商会在服务端拦截以下内容，命中会直接返回失败。规避方式不是换措辞硬试，而是换方案：

- **真实公众人物** —— 用虚构人物描述替代，不要指名真人。
- **性内容** —— 直接不做。
- **商标 / 受版权保护的角色** —— 用相似的通用描述替代，不要在提示词里写品牌名或 IP 角色名。

**提示词里出现品牌名、人名、具体商标时容易触发拦截**。若视频生成返回 HTTP 400，
优先检查提示词里有没有这类词，简化后重试；确有 4K / 超长时长等更高能力需求时再考虑
显式指定模型，但要清楚能力越强的模型通常版权/隐私策略越严。

## 一条总结

**具体 > 抽象，正面 > 否定，扩写 > 原样透传。** 用户给你一句需求，你的工作是把它变成
一段能直接喂给模型的、有画面感的描述——这是这个技能存在的全部理由。
