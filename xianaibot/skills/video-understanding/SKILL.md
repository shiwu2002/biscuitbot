# 视频理解（video-understanding）

> 本技能给出的是「**按成本从低到高地问一段视频要信息**」的方法：
> 先拿免费的元数据，再拿便宜的语音文字稿，最后才在**画面本身重要**时抽几张帧看图。
>
> 它**不提供把视频送进模型的通道**——视频像素永远不进上下文（成本差 2–3 个数量级，
> 本项目因此拒绝了自动视频理解）。声音走 ASR，画面走「抽几帧当图片看」。
>
> **红线：禁止整片逐帧扫描。** 10 分钟视频逐帧可达数十万 token，这正是本项目
> 砍掉自动视频理解的原因——本技能存在的意义就是给出它的替代路径。

## 何时用

- 用户发了视频文件：消息里会带 `[用户附加视频：<路径>…]`（那里同时说明了画面不会自动解析）。
- 用户把视频**链接**写在了正文里（链接不是附件，界面上没有直链入口）。
- 用户问：「里面说了什么」「讲了什么故事」「这个人演示了什么」「第 3 页的图表画的是什么」。

不要用本技能的场景：

- 要**生成 / 剪辑**视频 → `generate_video_seedance`、`jianying-editor`、`short-drama-production`。
- 纯音频文件（`.mp3` / `.wav` / `.m4a`）→ 直接 `transcribe_media`，不用探测也不用抽帧。
- 只是想**转发/保存**这段视频 → 不需要理解，别去转写。

## 成本阶梯：从上往下走，够用就停

| 级别 | 手段 | 成本量级 | 什么时候用 |
|---|---|---|---|
| **L0** | `ffprobe` 读元数据 | **免费** | **永远先做这步**：拿到时长 / 分辨率 / 有没有音轨，据此选下面哪条路 |
| **L1** | `transcribe_media` 转写语音 | 按音频秒数计费，10 分钟 ≈ 几 k token | 用户问的是**内容 / 说了什么**——多数问题到这里就够了 |
| **L2** | `ffmpeg` 抽 6–12 帧 + `read_file` 逐张看 | 每张约几百 token，12 张 ≈ 5–10k token | 只有**画面本身**重要时（演示、图表、画面里的文字） |
| **L3** | 先 `curl.exe` 下载链接，再回到 L0 | L0–L2 的成本 + 下载耗时 | 用户给的是链接而不是文件 |

**先跑 L0 再决定**，不要一上来就转写或抽帧——一段没有音轨的纯画面视频转写只会浪费一次调用。

## L0 探测（免费，永远先做）

```bash
ffprobe -v error -show_entries format=duration,size,format_name -show_entries stream=codec_type,width,height -of default=noprint_wrappers=1 clip.mp4
```

读到的结果决定下一步：

- 有音轨 + 用户问内容 → L1。
- 没有音轨（纯画面、无声监控、录屏）→ 直接 L2，别调转写。
- 时长很长（> 30 分钟）→ 你只会抽样看，回答里要说明这一点。

## L1 语音：先试最省的那条路

**文件没超过上限时直接转写**——`transcribe_media` 会把整个容器交给 ASR，这一步不需要 ffmpeg：

```
transcribe_media(path="clip.mp4")
```

上限是配置项 `transcription.max_upload_mb`（默认 25 MB）。**超过上限时**，先抽一条低码率单声道音轨（10 分钟 ≈ 2–3 MB），再转写这条音轨：

```bash
ffmpeg -y -loglevel error -i clip.mp4 -vn -ac 1 -ar 16000 -c:a aac -b:a 32k clip_audio.m4a
```

```
transcribe_media(path="clip_audio.m4a")
```

两条纪律：

- **同一个文件不要重复调用**（每次都计费，结果完全一样）。转写结果已经在上文里了，直接读。
- 正文里若已有 `[transcription: …]`（飞书 / 微信的语音消息自带），**直接用那段文本**，不要再调工具。

## L2 画面：只抽少量帧

画面问题才抽帧，并且按「时长 ÷ 帧数」算间隔，抽 6–12 张、宽度缩到 640（token 与分辨率正相关）：

```bash
ffmpeg -y -loglevel error -i clip.mp4 -vf "fps=1/30,scale=640:-2" -frames:v 12 clip_f_%02d.jpg
```

`fps=1/30` 表示每 30 秒一张（6 分钟的视频正好 12 张）；按时长换分母——3 分钟用 `1/15`，30 分钟用 `1/150`。

然后逐张看：

```
read_file("clip_f_01.jpg")
```

（`read_file` 会把 PNG / JPEG 渲染成能看的图片；这正是「抽帧」能替代视频理解的原因。）

输出写到**工作区根目录**（`exec` 的 cwd 就是工作区），不要写系统临时目录——否则后续 `read_file` 的路径解析会被工作区边界拦下。

**帧数就是成本开关**：12 张约 5–10k token，100 张就是十倍。抽样看过的，回答里要说「我按间隔抽看了 N 帧」，**不要暗示逐帧看过**。

## L3 链接：先下载，再按上面的阶梯走

```bash
curl.exe -L --fail --max-time 300 -o clip.mp4 "https://example.com/clip.mp4"
```

三个必须知道的坑：

1. **Windows 上必须写 `curl.exe`，不能简写成 `curl`**：`exec` 里**多行**命令走 PowerShell，那里的裸 `curl` 是 `Invoke-WebRequest` 的别名，不认 `-o`（单行命令走 cmd，`curl` 恰好能用——但写 `curl.exe` 两种情况下都对，所以统一这么写）。
2. **只支持直链文件**（`.mp4` / `.mov` / `.webm` / `.m3u8` 这类以文件结尾的地址）：B 站 / YouTube / 抖音那种**页面链接下不了**——本机没有 yt-dlp。遇到页面链接就如实告诉用户「这类平台链接需要你自己下载后上传」。
3. **下完先 `ffprobe` 验一下**：下到 HTML 错误页时文件会存成同名 `.mp4`，`ffprobe` 报 `Invalid data found` 就是没下到视频，别硬当视频处理。

内网 / 本机地址（`192.168.*`、`127.0.0.1`、`localhost`）会被 SSRF 防护拦下。这是**硬性安全策略**，不是配置问题：不要换写法重试，直接告诉用户。

## 降级：能力缺失时怎么说

| 情况 | 表现 | 你该做的 |
|---|---|---|
| 没装 ffmpeg | `ffmpeg` / `ffprobe` 命令不存在 | 只能走 L1 且文件 ≤ 上限。**明说取不到画面**，并建议安装（Windows `winget install Gyan.FFmpeg`，macOS `brew install ffmpeg`） |
| ASR 未配置 | `transcribe_media` 返回「未配置 API Key…」 | 把该错误原样转达（它自带修复路径），并说明这次只有画面层面的信息 |
| 平台页面链接 | 下载到的是 HTML 而不是视频 | 请用户自己下载后上传，不要反复换命令重试 |
| 文件超上限且没有 ffmpeg | `transcribe_media` 报「文件过大」 | 如实说明：既压不了音轨，也传不上去 |

**任何一项缺失都要说出来。** 用户宁可听到「我没看到画面」，也不要一个顺着他的问题编出来的答案。

## 反面清单

| 别做 | 后果 |
|---|---|
| **整片逐帧扫描**（`fps=1` 把整片抽成几百帧） | token 爆炸（10 分钟可达数十万）——本技能的红线 |
| 试图把视频文件当附件发给模型 | 没有这个通道，也发不出去 |
| 对同一文件重复调 `transcribe_media` | 每次都付费，结果完全相同 |
| 假装看过画面 | 比明说看不到糟糕得多 |
| 在 Windows 上用裸 `curl` 下载 | 多行命令会落到 PowerShell，那里它是 `Invoke-WebRequest` 别名，命令失败 |
| 把抽出的帧 / 下载的副本留在工作区不管 | 可接受，但任务结束时说一句更好 |

## 交付

- 转写文字稿要成文件，就用 `write_file` 写进工作区再发；只回答问题则直接把关键内容整理成答复。
- 抽出的帧（`clip_f_*.jpg`）与下载的副本（`clip.mp4`、`clip_audio.m4a`）是过程产物：任务结束可以删掉，也可以在交付时说明它们留在工作区哪里。
